# Trend Executor 本地自动交易系统

## 已实现

- Binance USDT 永续合约涨幅榜扫描；
- 从榜单第 1 名向下选择排名最高的合格币；
- 15m、1h、4h、1d 已完成 K 线方向过滤；
- 5m、15m、1h、4h、1d 最后一根已完成 K 线全部位于 Supertrend 线上时入场，无需等待新的 5m 突破；
- 每个通道同时只持有一个多头仓位；
- 锁定五周期同向的最高排名币；若其风险不合格则保持空仓等待，不跳到下一名；
- 持仓期间出现排名更高且五周期、实时风险全部合格的首位目标时，先平旧仓再自动换入；
- 全仓模式，按实时价格到5m趋势线的跌幅自动选择10、8、6、4、2倍杠杆；
- 下单基数取账户权益与可用余额较小值，默认预留2%保证金缓冲；
- 自动读取该币种和当前杠杆的交易所最大名义价值，并遵守市价单最大数量，超限时缩小仓位；
- 交易所明确返回保证金不足或当前杠杆最大仓位超限时逐级缩量重试，订单状态未知时禁止盲目重发；
- 实时趋势线跌幅最多10%，据此计算的理论账户风险最多20%；
- `Supertrend - ATR`硬止损仅作额外保护，不参与杠杆计算；
- 杠杆只按实时价格到5m趋势线的跌幅分档，硬止损距离不参与杠杆计算；
- 5m 收盘跌破 Supertrend 的软退出；
- `Supertrend - N×ATR` 标记价格硬止损；
- 实盘保护单使用 Binance USDⓈ-M Algo Order 条件订单接口；
- 硬止损单向上移动；
- 跌出榜单立即退出；
- 策略退出旧仓后立即重新扫描首位目标，不等待下一根5m K线；
- 页面独立统计自动换仓次数并标记当前持仓与换仓目标；
- 页面显示保证金缓冲参数与保证金缩量重试次数；
- 纸面交易与Binance实盘双引擎并行运行；
- 两套引擎的仓位、统计、日志和API凭据完全隔离；
- 实盘数据与操作由服务端访问密码保护，使用8小时HttpOnly会话和登录失败限流；
- 账户与已有持仓恢复、硬止损接管；
- 启动、停止新开仓和紧急平仓；
- 本地前端展示动态杠杆计划、理论风险、榜单、持仓、参数、统计和事件日志。

## 启动

需要 Node.js 22.13 或更高版本。

```bash
cd dashboard
npm install
cp .env.example .env.local
npm run dev
```

启动前编辑 `.env.local`，设置本地实盘访问密码。该文件已被Git忽略，不会提交到仓库。

浏览器打开：

```text
http://localhost:3000
```

命令会同时启动：

- 前端控制台：`http://localhost:3000`
- 纸面交易引擎：`http://localhost:3001`
- 实盘交易引擎：`http://localhost:3002`

## 推荐验证顺序

1. 纸面交易；
2. Binance Futures 测试网；
3. 核对至少 100 个信号和全部退出路径；
4. 单独审查真实订单、保护单和异常恢复；
5. 最后才考虑实盘。

## API 凭据

实盘连接需要 API Key 与 Secret Key。凭据由浏览器发送至独立实盘引擎 `127.0.0.1:3002`，仅保存在该进程内存中：

- 不写入文件；
- 不写入浏览器存储；
- 不写入日志；
- 关闭本地服务后清除。

建议为系统创建单独的 API Key：

- 只开启合约读取和交易权限；
- 禁止提现；
- 绑定本机出口 IP；
- 不复用主账户其他系统的密钥。

## 三种模式

### 纸面交易

不需要密钥，使用生产市场公开行情和 10,000 USDT 模拟权益。不会向 Binance 发送订单。

### 测试网

使用 Binance Futures 测试网账户和测试网密钥。公开策略行情仍从生产市场读取，但只选择测试网支持的合约。

### 实盘

需要实盘 API Key、Secret Key 和页面显示的解锁短语。连接只验证账户，不会立即启动；还必须再次点击“启动自动交易”。

## 重要操作语义

- “停止新开仓”：禁止新增仓位，但不会主动平掉已有仓位；交易所硬止损继续保留。
- “紧急平仓”：撤销当前保护单并使用只减仓市价单退出，同时停止策略。
- 程序关闭：不会自动撤掉交易所硬止损。
- 重新连接：核对实际持仓，并接管唯一一个全平 `STOP_MARKET` 保护单。
- 如果检测到多个持仓、空头持仓或多个全平硬止损，策略停止并要求人工核对。

## 当前边界

该项目是可运行的本地交易系统基线，不是经过长期实盘验证的交易基础设施。尤其需要继续验证：

- 测试网与实盘账户的订单字段差异；
- 不同币种的价格与数量精度；
- 快速行情下的成交滑点；
- 网络超时后订单状态不确定的恢复；
- 榜单第 10/11 名频繁切换造成的换手；
- 本地电脑休眠、断网和进程崩溃；
- Binance API版本、限频和交易规则变化。

在完成测试网全流程验证前，不建议启用实盘。
